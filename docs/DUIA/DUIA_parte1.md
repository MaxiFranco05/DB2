| **Herramienta** | opencode (nemotron-3-ultra-free) |
| **Spec o prompt utilizado** | Usuario solicitó 3 reglas de negocio PostgreSQL:<br/>1. **Máquina de estados**: Trigger BEFORE UPDATE en `pedido` que impida cambiar `estado` si OLD.estado ∈ ('CANCELADO', 'TERMINADO')<br/>2. **Catálogo activo**: Trigger BEFORE INSERT en `detalle_pedido` que impida INSERT si `producto.activo = FALSE`<br/>3. **Control de stock**: Trigger BEFORE INSERT en `detalle_pedido` que verifique `cantidad ≤ producto.stock`, lance excepción si mayor |
| **Qué generó** | Archivo `db/restricciones.sql` con:<br/>- `validar_transicion_estado_pedido()` + `trg_validar_estado_pedido` (pedido, UPDATE)<br/>- `validar_producto_activo()` + `trg_01_validar_producto_activo` (detalle_pedido, INSERT)<br/>- `validar_stock_producto()` + `trg_02_validar_stock` (detalle_pedido, INSERT)<br/>- `ALTER TRIGGER trg_subtotal RENAME TO trg_03_calcular_subtotal` (orden ejecución)<br/>Archivo `db/test_restricciones.sql` con DO block PL/pgSQL para pruebas automatizadas |
| **Qué se aceptó** | - Las 3 funciones trigger y sus triggers correspondientes<br/>- Renombrado de trigger existente para control de orden (prefijos numéricos 01, 02, 03)<br/>- Mensajes de error en español consistentes con schema<br/>- Transacción explícita `BEGIN; ... COMMIT;` en restricciones.sql<br/>- Nomenclatura snake_case según steering rules |
| **Qué se modificó o descartó, y por qué** | - **Script de pruebas original**: Usaba `\set var \`SELECT...\`` (shell backticks) y `LIMIT` en UPDATE (sintaxis MySQL). No funcionaba en psql script mode.<br/>- **Corregido a DO block PL/pgSQL**: Variables reales, EXCEPTION blocks para capturar errores esperados, RAISE NOTICE para logging limpio.<br/>- **Orden triggers**: Verificado vía `information_schema.triggers.action_order` → validaciones (1,2) corren antes que subtotal (3). |
| **Verificación realizada** | Ejecutado en clon `food_store_test` (protocolo seguridad):<br/><br/>**REGLA 1 - Máquina de estados**:<br/>- UPDATE TERMINADO→PENDIENTE: **ERROR** "No se puede modificar el estado del pedido X: ya está TERMINADO" ✅<br/>- UPDATE CANCELADO→CONFIRMADO: **ERROR** "No se puede modificar el estado del pedido X: ya está CANCELADO" ✅<br/>- UPDATE PENDIENTE→CONFIRMADO: **OK** ✅<br/>- UPDATE CONFIRMADO→TERMINADO: **OK** ✅<br/>- UPDATE TERMINADO(recien)→CANCELADO: **ERROR** ✅<br/><br/>**REGLA 2 - Catálogo activo**:<br/>- INSERT producto ACTIVO: **OK** (subtotal calculado) ✅<br/>- INSERT producto INACTIVO: **ERROR** "No se puede agregar el producto X: el producto está inactivo" ✅<br/>- Cambiar activo→FALSE y luego INSERT: **ERROR** ✅<br/><br/>**REGLA 3 - Control de stock**:<br/>- INSERT cantidad = stock (3): **OK** ✅<br/>- INSERT cantidad < stock (1): **OK** ✅<br/>- INSERT cantidad > stock (5>3): **ERROR** "Stock insuficiente para producto X: solicitado 5, disponible 3" ✅<br/>- INSERT stock 0: **ERROR** "Stock insuficiente... disponible 0" ✅<br/><br/>**ORDEN TRIGGERS**:<br/>- `action_order`: 1→`trg_01_validar_producto_activo`, 2→`trg_02_validar_stock`, 3→`trg_03_calcular_subtotal` ✅<br/>- Test orden: Error por "Stock insuficiente" (Regla 3), NO por subtotal ✅ |
