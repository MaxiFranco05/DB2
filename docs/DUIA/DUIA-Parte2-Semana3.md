# DUIA - Parte 2: Creación de Índices de Optimización (Semana 3)

| **Herramienta** | Generación de script SQL transaccional PostgreSQL para índices (OpenCode) |
| **Spec o prompt utilizado** | "Crear script db/indices.sql que consolide los 3 índices necesarios para optimizar escaneos secuenciales en Food Store. Dos índices ya existían en db/schema.sql; el tercero (parcial) es nuevo. Evaluar opciones: A) Agregar a schema.sql, B) Agregar a restricciones.sql, C) Crear db/indices.sql dedicado. Justificar decisión." |
| **Qué generó** | Script db/indices.sql idempotente con BEGIN/COMMIT: 1) idx_producto_categoria (ya en schema.sql) ON producto(categoria_id); 2) idx_pedido_usuario (ya en schema.sql) ON pedido(usuario_id); 3) idx_producto_precio_activo (NUEVO - índice parcial) ON producto(precio) WHERE activo = true. Decisión arquitectura: Opción C elegida - archivo dedicado a performance por separación de preocupaciones, versionable, re-ejecutable. Principio Single Responsibility: schema = DDL base, restricciones = lógica negocio, indices = performance. Idempotencia con CREATE INDEX IF NOT EXISTS. |
| **Qué se aceptó** | La arquitectura de archivo separado db/indices.sql, los 3 índices con CREATE INDEX IF NOT EXISTS, el índice parcial WHERE activo = true, la justificación de separación de responsabilidades, la idempotencia del script |
| **Qué se modificó o descartó, y por qué** | Opción A (agregar a schema.sql): descartada — rompe idempotencia de schema; schema = estructura mínima. Opción B (agregar a restricciones.sql): descartada — confunde restricciones lógicas vs optimización física. Opción C (crear db/indices.sql): elegida — separación de preocupaciones, versionable, re-ejecutable, cumplimiento Steering Rules (no rompe 3NF, son optimizaciones puras). Justificación final documentada en tabla "Opciones Evaluadas" con veredicto por opción. |
| **Verificación realizada** | Prueba de equivalencia con EXCEPT bidireccional comparando planes de ejecución antes/después. Ejecución script y verificación: SELECT indexname, tablename, indexdef FROM pg_indexes WHERE indexname IN ('idx_producto_categoria','idx_pedido_usuario','idx_producto_precio_activo') — 3 índices creados ✅. EXPLAIN ANALYZE en 3 queries típicas: categoria_id = 1 → Index Scan usando idx_producto_categoria ✅; usuario_id = 123 → Index Scan usando idx_pedido_usuario ✅; activo=true AND precio BETWEEN 1000 AND 2000 → Index Scan usando idx_producto_precio_activo ✅. Impacto rendimiento con 50K productos, 200K pedidos: productos por categoría 10-50x ✅, pedidos por usuario 4K-200Kx ✅, productos activos por precio 7-35x ✅. |
